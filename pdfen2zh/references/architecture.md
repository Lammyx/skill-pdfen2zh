# pdfen2zh：功能分析与模块拆分

2026-11-12。目标是在本 Skill 内提供文件输入/输出的独立命令行，不依赖 PDFtranslate 项目路径、桌面服务或文库数据库。底层继续使用锁定的 BabelDOC 0.6.4，迁入现有文本保护与局部修复适配代码。

对外名称、技能目录、调用名和分发 ZIP 根目录统一为 `pdfen2zh`。已有任务的 adapterVersion 保留原标识，避免改名导致旧译文无法继续修复。

## 功能边界

| 功能 | 实现位置 | 提取决策 |
| --- | --- | --- |
| PDF 解析、版面分析、中文排版、mono/dual | BabelDOC | 保留引擎与版本 |
| OpenAI-compatible 接口、重试、截断/空响应检查 | ai/provider、generation、translation/openai_adapter | 独立配置，只从显式参数/本技能环境变量读取 |
| 学术翻译、术语、正文/摘要/附录选择 | translation/settings、sections | 抽出纯设置，术语来自 JSON，不再读取项目表 |
| 公式/占位符、标题碎片、斜排字形保护 | quality、title_fragments、rotated_text | 保留版本匹配的进程内适配 |
| 成功片段缓存、按页缓存重放与有限补译 | cache、repair、repair_cache | 以独立任务 manifest 代替阅读器 job ID 的查找 |
| 空白斜排标签恢复、重复页眉统一 | layout_repair | 在独立产物阶段调用；保留原文标签不等于完成中文翻译 |
| 原文只读、路径/页数/散列校验、局部页替换 | jobs、repair_results | 在文件任务层重建，保留旧版本 |
| 请求用量、缓存命中、未知用量、失败报告 | ai/usage | 独立任务账本，不接入现有文库 |
| 桌面窗口、Zotero、项目、索引、对话 | 原阅读器 | 留在原项目，不迁入 |

## 执行流程

```text
命令参数 / 环境配置 / 术语 JSON
  → 校验输入 PDF、页码与配置
  → 新建任务目录，复制输入并保存散列
  → 独立工作进程：结构分析 → 选择文本 → 查片段缓存 → 翻译缺失内容 → 排版
  → 验证原文及引擎输入未变、mono/dual 路径与物理页数
  → 恢复空白图表标签并统一重复页眉
  → 保存中文 PDF、并排双语 PDF、质量/范围/用量报告、局部补译记录
```

修复分为两条路径：`repair --pages ...` 默认只重放已有缓存；显式给出新请求上限才允许补译；`repair --layout-only` 只操作现有 PDF，不运行翻译模型。普通翻译或修复均生成新任务目录，不覆盖输入或旧产物。

## 模块职责

- `scripts/translate_pdf.py`：命令入口、错误退出码；帮助与环境诊断无需启动翻译。
- `scripts/pdf_backend/config.py`：参数、术语 JSON、独立环境变量和翻译设置。
- `scripts/pdf_backend/workspace.py`：任务目录、manifest、散列与 PDF 产物校验。
- `scripts/pdf_backend/pipeline.py`：普通翻译、缓存补译、本地修复的流程组织与报告。
- `scripts/pdf_backend/translation/`：原 BabelDOC 进程协议、缓存、文本保护和排版适配。
- `scripts/pdf_backend/ai/`：接口配置、请求预算与用量账本。
- `references/usage.md`：环境安装、命令示例、产物与能力边界。

## 独立性与兼容点

1. 删除 `settings → library.glossary → Storage` 导入链；学术提示词与设置版本在本地纯模块中保存。
2. worker 的模块名改为 `pdf_backend.translation.worker`；子进程显式获得技能 scripts 路径，与当前工作目录无关。
3. 源目录、原任务记录与补译基准均由 manifest 明确绑定。修复核对输入和旧产物散列，不按标题猜测，也不从其他阅读器任务导入设置。
4. 保留默认 BabelDOC 用户资源缓存；可指定独立缓存目录。资源预热是显式命令，诊断不下载资源。
5. 模型密钥不保存在 Skill、manifest 或公开事件中；任务只记录端点与模型身份。跨机器使用仍需安装依赖与准备布局/字体资源。
6. 复制的源码保留 AGPL-3.0 许可证和来源清单；字体/模型资源不随 Skill 打包。

## 验证顺序

先验证技能格式与依赖独立性，再验证临时目录中的 PDF 输入/输出、任务清单、缓存修复、失败报告及取消行为。具备本机资源时，以本地模拟接口运行实际引擎，报告为工程验证。真实论文翻译与语义质量验证需明确具体输入后执行；本次不调用真实模型服务。

## 实施结果（2026-11-12）

- 上述八个模块已接入独立 CLI，安装于本技能目录；原 PDFtranslate 源码和文库未改动。纯配置移除了 `settings → library.glossary → Storage` 依赖，导入检查没有加载 `reader_service`。
- 实施时曾依据独立 `uv.lock` 离线安装运行环境，未复制原项目虚拟环境。doctor 确认 BabelDOC 0.6.4、布局模型、34/34 字体、146/146 CMap、1/1 tokenizer 可用；使用时仍需安装与预热。
- 4 项文件流程测试通过：原文保护、产物/清单、局部页保留、基准修改拒绝、失败/取消落盘和参数边界；另 3 项修复测试验证缓存缺失不发送、权限单次使用和新请求硬上限。
- 真实 BabelDOC 子进程在任意工作目录下处理 1 页合成 PDF，经本地模拟接口的 2 次请求生成中文与双语 PDF；两份产物各 1 页，均可提取 21 个中文字符，已渲染检查。它验证运行链路，不证明论文翻译语义质量。
- 模拟接口关闭后，针对同一任务执行实际缓存修复成功：复用 1 个单元、替换 1 页、0 新请求、0 缺失单元。原始输入散列保持不变。
- 实施时技能格式校验、Ruff、Python 编译检查通过，真实 LLM/embedding 请求为 0，未下载模型资源。分享目录已移除测试代码、模拟产物、本机虚拟环境与缓存；以上为清理前的验证记录，不随技能分发测试产物。

已知边界：首版通过 JSON 接入手工术语，未提供自动提取术语选项；斜排标签可能保留英文。扫描/OCR、表格和复杂论文版式仍需具体材料验证。修复依赖本技能保存的清单与片段记录，旧阅读器任务没有直接导入入口。

## 分享适配与解压验收（2026-11-12）

- 新增无第三方依赖的 `launch.py`，按入口位置寻找技能目录；`init` 通过 uv 创建独立 Python 3.11 环境，日常命令检查依赖，使用 `-B` 避免写入字节码缓存。原后端 CLI 保留。
- `config.example.json` 提供端点、模型、空密钥、缓存、超时及代理示例。本地配置默认 `config.local.json`，环境变量优先，CLI 显式参数优先级最高。相对缓存/证书路径绑定配置文件目录。
- 修复使用当前机器缓存，不读取基准 cacheDirectory 作为执行路径；旧路径保留于 baseManifest.cacheDirectoryAtCreation。任务产物路径写为 `/` 分隔相对路径，兼容旧 Windows 反斜线；旧原文路径不参与迁移后的基准读取。
- `scripts/package_skill.py` 使用固定公开文件和 Python 源码白名单，输出目录外的新 ZIP，保留许可证；不打包本地配置、环境、PDF、任务或缓存。
- 从 ZIP 解压到含中文、空格的新路径，在任意工作目录完成初始化与命令调用。初始目录没有虚拟环境，安装 85 个依赖；宿主已有 Python/uv，安装使用本机包缓存，因此不是完全空白物理机器验收。
- 独立空资源缓存初始为模型缺失、字体 0/34、CMap 0/146、tokenizer 0/1；显式 warmup 下载后全部散列校验通过。未复制原阅读器资源作为这一项验收输入。
- 实际 BabelDOC 处理两页合成正文，经本地模拟接口 3 次请求生成中文与双语 PDF，中文产物提取 50 个汉字；原始输入散列未变。将完整任务迁移并把原文/缓存路径改成不存在的旧机器路径后，0 新请求修复第 1 页，第 2 页像素不变；本地排版修复也完成。
- 另建仅含字体/布局资源、没有 cache.v1.db 的当前机器缓存，服务已关闭；从迁移任务的片段清单复用 1 个单元，0 新请求修复第 1 页。迁移修复不要求复制原机器的译文缓存数据库。
- 配置优先级、相对缓存解析、非法配置不回显测试密钥、包含运行数据的目录重新打包、目录内 ZIP 输出拒绝均通过。ZIP 不含测试密钥或文献，许可证内容保持一致。验收脚本、虚拟环境和产物保存在技能目录之外。

验收边界：仅实测 Windows x64 / Python 3.11.9，未验收 macOS/Linux/ARM 或真实供应商；真实 LLM/embedding 请求为 0。本地模拟接口验证工程链路，不验证译文语义质量。极稀疏的双页合成文本曾被上游 ScannedPDFError 拒绝，采用正常正文密度的合成 PDF 后通过，未修改引擎的扫描检测逻辑。免安装、免配置需要另行封装运行时/资源并提供翻译服务，不属于本源码 skill。

## v0.2.0：API 与当前助手双模式（2026-11-13）

原 `translate` API 入口保持不变。新增 `agent-export → 当前助手填写译文 → agent-check → agent-render` 文件交接流程；命令本身不会自动驱动当前对话。操作格式见 [agent-workflow.md](agent-workflow.md)。

- `agent_files.py` 负责源文件/导出清单绑定、分批模板、覆盖检查、重复/未知 ID 与占位符校验。
- `translation/agent.py` 复用引擎实际预处理文本和样式/公式占位符，以页码、段落序号及原文散列定位单元；在工作进程中导出或回填，不创建 OpenAI 客户端。任何意外的翻译调用均停止，不回退 API。
- 导出清单状态为 awaiting_translation，outputs 为空，避免将英文中间产物当成已完成中文译文。回填要求全部非空译文，重新解析不一致或后处理拒绝时不发布成功结果。
- 助手任务使用 agent://local / conversation-v1 标识文件来源，不冒称识别了当前助手的具体模型版本。API 账本只记录独立翻译请求；当前对话用量标为 not_measured。
- 已保存的导出单元、批次译文和成功产物可迁移。修改一个译文文件后，可复用其余译文重新排版；该步骤仍重新运行引擎，不能宣称省去解析/排版计算。

针对性核查：Windows x64 / Python 3.11.9 上，实际引擎导出两页、两个单元及两份批次模板。本次对话提供中文译文后回填成功，中文 PDF 提取 324 个汉字；中文与并排双语产物均为两页，代表页经 Poppler 渲染查看。测试钩子拦截 OpenAI 客户端构造及 HTTP 发送，两阶段仍完成且没有触发拦截，API 请求为 0。空译文在排版前拒绝；原文/清单散列、重复/未知 ID、字段类型与损坏公式/样式标记等 7 项错误输入均被拒绝。API 模式经本地模拟接口的 3 次请求回归通过，真实 LLM/embedding 请求为 0。测试脚本、缓存和 PDF 不放入分发技能目录。

补充失败/修复核查：将一个长英文单元原样返回，实际排版被 AGENT_TRANSLATION_REJECTED 拒绝，清单为 failed、outputs 为空；随后对成功助手产物进行默认缓存修复，0 新请求替换第 1 页，第 2 页像素不变。对助手产物设置正数 API 补译预算会在创建任务前停止。
